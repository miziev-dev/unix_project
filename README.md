## Описание проекта

Проект реализует развертывание защищённой NoSQL СУБД **MongoDB 6** в режиме **Replica Set**
(Primary + Secondary + Arbiter) на базе Docker Compose. Инфраструктура полностью
автоматизирована: от первичной подготовки хоста (bootstrap.sh) до резервного копирования
и интеграционного тестирования.

**Решаемые задачи:**

- Развёртывание MongoDB с обязательной аутентификацией (`--auth`)
- Настройка кластера Replica Set (`rs0`) для обеспечения высокой доступности
- Автоматизированное резервное копирование коллекций через `mongodump` с ротацией архивов
- Хранение конфигурации на хосте с монтированием в контейнер (read-only)
- Интеграционные тесты работоспособности кластера

## Быстрый старт

### 1. Клонирование репозитория

```bash
git clone <url-репозитория>
cd os_project
```

### 2. Настройка переменных окружения

```bash
cp .env.example deploy/.env
# Откройте файл deploy/.env и замените значения паролей на свои:
nano deploy/.env
```

### 3. Подготовка хоста и запуск кластера

Все шаги объединены в одну команду:

```bash
make up
```

Эта команда выполняет последовательно:
- `make setup` — генерирует ключ репликации (`replica.key`), создаёт нужные директории
- `make hardening` — настраивает UFW, устанавливает права на файлы ключей
- `docker compose up -d --build` — собирает и запускает все контейнеры

### 4. Инициализация Replica Set

После первого запуска необходимо вручную инициализировать кластер:

```bash
docker exec -it mongo-primary mongosh \
  -u admin -p <ваш_пароль> \
  --authenticationDatabase admin \
  --file /scripts/init-replica.js
```

### 5. Проверка статуса

```bash
make ps       # статус контейнеров
make test     # запуск интеграционных тестов
```

## Конфигурация

Все параметры хранятся в файле `deploy/.env` (создаётся из `.env.example`).
Файл `.env` **никогда не коммитится в Git**.

| Переменная                       | Описание                                   | Пример             |
|----------------------------------|--------------------------------------------|--------------------|
| `MONGO_INITDB_ROOT_USERNAME`     | Имя пользователя-администратора MongoDB    | `admin`            |
| `MONGO_INITDB_ROOT_PASSWORD`     | Пароль администратора (задайте свой!)      | `<ваш_пароль>`     |
| `MONGO_REPLICA_SET_NAME`         | Имя Replica Set                            | `rs0`              |
| `ME_CONFIG_BASICAUTH_USERNAME`   | Логин для доступа к Mongo Express          | `devops`           |
| `ME_CONFIG_BASICAUTH_PASSWORD`   | Пароль для доступа к Mongo Express         | `<ваш_пароль>`     |

Конфигурация самого демона MongoDB хранится в `config/mongodb/mongod.conf`
и монтируется в контейнер в режиме **read-only**.

## Управление кластером

Все операции выполняются через `Makefile`:

```bash
make up         # Подготовка хоста + применение политик безопасности + запуск кластера
make down       # Остановка кластера (данные сохраняются)
make clean      # Полная очистка: остановка + удаление volumes и ключей (ДАННЫЕ УДАЛЯТСЯ!)
make backup     # Создать резервную копию всех баз данных
make test       # Запустить интеграционные тесты
make hardening  # Применить политики безопасности ОС (UFW, права файлов)
make logs       # Просмотр логов всех контейнеров в реальном времени
make ps         # Статус контейнеров
```

### Прямое подключение к MongoDB

```bash
# Подключение через mongosh внутри контейнера
docker exec -it mongo-primary mongosh \
  -u admin -p <пароль> \
  --authenticationDatabase admin

# Проверка состояния Replica Set
docker exec -it mongo-primary mongosh \
  -u admin -p <пароль> --authenticationDatabase admin \
  --eval "rs.status()"
```

### Веб-интерфейс Mongo Express

После запуска кластера доступен по адресу: **http://localhost:8081**

Логин/пароль задаются в `.env` через переменные `ME_CONFIG_BASICAUTH_*`.

## Резервное копирование

Резервное копирование выполняется скриптом `deploy/scripts/backup.sh`:

```bash
make backup
# или напрямую:
bash deploy/scripts/backup.sh
```

**Что делает скрипт:**
1. Запускает `mongodump` внутри контейнера `mongo-primary` с gzip-сжатием
2. Копирует архив на хост в директорию `backups/`
3. Автоматически удаляет архивы старше **7 дней** (ротация)

Формат имени файла: `mongo_backup_YYYY-MM-DD_HH-MM-SS.gz`

**Для автоматического резервного копирования** добавьте задание в cron:

```bash
# Ежедневно в 03:00
0 3 * * * cd /path/to/os_project && bash deploy/scripts/backup.sh >> /var/log/mongo_backup.log 2>&1
```

**Восстановление из резервной копии:**

```bash
# Скопируйте архив в контейнер
docker cp backups/mongo_backup_<timestamp>.gz mongo-primary:/tmp/

# Выполните восстановление
docker exec -it mongo-primary mongorestore \
  -u admin -p <пароль> \
  --authenticationDatabase admin \
  --archive=/tmp/mongo_backup_<timestamp>.gz \
  --gzip
```

## Тестирование

Интеграционные тесты расположены в `deploy/scripts/tests/test_mongo.sh`.

```bash
make test
```

**Тесты проверяют:**
1. Доступность MongoDB (ожидание готовности до 60 секунд)
2. Статус Replica Set (`rs.status().ok == 1`)
3. Базовую операцию записи в базу данных

**Ожидаемый вывод при успехе:**

```
LOG: MongoDB Primary готова!
LOG: Тест 1. Проверка состояния Replica Set...
SUCCESS: Replica Set активен.
LOG: Тест 2. Проверка операции записи...
SUCCESS: Запись в базу прошла успешно.
---------------------------------------
ИТОГ: Все тесты пройдены успешно!
```

## Безопасность

Скрипт `security/hardening.sh` выполняет следующие действия:

- Устанавливает права `400` на файл ключа репликации (`replica.key`)
- Настраивает **UFW** по принципу «запрещено всё, что не разрешено явно»:
  - Порт `22/tcp` — SSH
  - Порт `80/tcp` — HTTP
  - Порт `443/tcp` — HTTPS
  - Порт `27017` — **закрыт снаружи** (MongoDB доступна только внутри Docker-сети)

**Включённые политики безопасности MongoDB** (`config/mongodb/mongod.conf`):

- `security.authorization: enabled` — обязательная аутентификация
- `security.keyFile` — взаимная аутентификация нод Replica Set по ключу
- Ограничение памяти WiredTiger (`cacheSizeGB: 1.0`) для защиты от OOM
